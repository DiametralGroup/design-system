# Audit — @diametral/ui against @diametral/design-system, 2026-10-13

Not a derived artifact. Records a full comparison of incoming (`@diametral/ui`,
diamorval/design-system-diametral `main` at `674bcb9`) with this package
(`5.0.0-beta.5`), and what was done about it under [`direction.md`](./direction.md):
**incoming is the model for code and design; any conflict is won by incoming; what
this package adds is kept.**

## Method

- **CSS, by resolved value.** Every rule of every incoming component stylesheet was
  parsed, each `var()` resolved through that side's own `:root` (light, then `.dark`),
  units normalised (rem → px), and compared declaration by declaration with this
  package's rule for the same selector. Textual diffs alone overstate the gap: most
  of the 1,021 textual differences were the `--ds-*` renames of decision 10.
- **React, by output.** Per component: exported names, `data-slot` values, `ds-*`
  classes and literal Tailwind classes rendered.
- **Tokens.** Every `--ds-*` token incoming declares, light and dark, resolved and
  compared.
- **Integration.** diamorval/diametral-ui-example, a real app on `diametral-ds`
  0.4.0, rebuilt on this package and compared screenshot by screenshot.

## Findings

| area | before | cause |
| --- | --- | --- |
| CSS declarations | 4,445 identical, **270 differing**, 211 incoming selectors missing, 276 declarations absent (light) | DiametralGroup restyles: Light 300 titles, 13px body, sentence-case 14px buttons, badge/tag/select-label voice, `--muted-foreground` mapped to `--ds-ink-soft` instead of incoming's `--ds-ink-faint` (50 rules), tone colours, a z-index scale, slider/switch sizes, sheet/drawer borders |

## What was done

1. **CSS regenerated from incoming** — `scripts/sync-incoming-css.mjs`. Incoming's
   rules first (slots mapped to `--ds-*` as incoming's own `:root` resolves them,
   layers kept, `.dark` widened to `[data-theme="dark"]`, `.dark`, `.dark-theme`),
   then a "DiametralGroup additions" block. A target-only rule that names only
   incoming classes restyles incoming's markup and is dropped (135 rules); one that
   reaches the 0.x plain-HTML grammar is kept. Classes both markups share
   (`.ds-checkbox`, `.ds-card`, `.ds-panel`, `.ds-stepper`, `.ds-tabs`, `.ds-field`,
   …) get a zero-specificity `:where(:not(:has(> legacy-child)))` guard on incoming's
   rules. Idempotent; edits to the additions block survive a re-run.
2. **React taken verbatim** from incoming, additions re-applied (see CHANGELOG).
3. **Layers, base, import order** adopted from incoming.
4. **Tailwind**: `css/tailwind.css` entry; `css/literals.css` precompiled for apps
   without Tailwind.
5. **Tokens**: incoming's dark values, English primitive aliases.

## Kept on purpose (conflicts not given to incoming)

- `--ds-green-brand` / `--ds-vert` = `#53ff64`: charter value confirmed in #161;
  incoming's `#89fc79` is off-charter (batch 0.3 planned the same fix upstream).

## Follow-ups

- **Docs site visual baselines** change by design; regenerate them in CI.
- **Blocks and 0.x pages** shift with incoming's defaults: `<Button>` without a
  variant is now solid black; P&L tables inherit incoming's line-height ratio in their
  13px cells; Light 300 titles are gone.
- **Registry prose** still describes some 0.x behaviour (`registry.ts`: speed-dial
  trigger, Stepper's 0.x grammar, `.ds-separator--auto`, `--plot`).
- **Site demos** are DiametralGroup's copies of incoming's (431 of 456 differ in
  imports or content); re-syncing them is the next step of decision 1.
- **Source ref.** Batches pinned `migration-source-v1`; this sync reads incoming's
  `main`. Re-run `scripts/sync-incoming-css.mjs` and re-take
  `packages/ui/src/components` whenever incoming moves.
